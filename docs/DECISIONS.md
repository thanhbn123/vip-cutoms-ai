- **D-030 · 2026-10-09 · Backup artifact permissions and consistency** (G16 supervisor correction): `scripts/production/backup.sh` created the dump, uploads archive and manifest under the caller's ambient umask, so under a normal `022` they were written **0644 — world-readable** on a host shared with eleven unrelated services, despite containing every customer document and audit record in plaintext. Fixed with `umask 077` *before* any file is created plus an explicit `chmod 600` per artifact (the chmods are the guarantee; the umask closes the creation-to-chmod window), `BACKUP_DIR` forced to `0700` and validated before use (refuses a symlink, a non-directory, or a directory not owned by the invoking uid), a post-write self-check that dies rather than leaving a readable dump, and `UMask=0077` on the systemd unit so it does not depend on the script alone. Covered by 13 execution tests that run the real script against a mocked `docker` under `umask 022` inside `tmp_path` — never against live data. Separately, the dump and the archive are taken **sequentially from a live stack and are therefore not an atomic snapshot**: `pg_dump` is internally consistent, `tar` over a live directory is not, and the two are seconds apart, so expect a few dangling document references around the backup window. `docs/PRODUCTION_RUNBOOK.md` §4 documents this plainly and gives the quiesced procedure (`stop api web` → backup → `start`) for when a coherent pair is required, points at filesystem/volume snapshots for coherence without an outage, and supplies a post-restore reconciliation command (verified to report `missing=0` when intact and to name the exact document id when one stored object is removed). Reversible: yes (config/script only, no schema change).

- **D-039 · 2026-10-09 · Human-closed issues reopen when the condition changes**: a RESOLVED (by a user) or WAIVED issue stays closed while re-evaluation detects the *same* condition (same evidence and title) — the human judgement stands — but reopens with an audited `issue.reopened` when the detected condition differs (new values, new evidence). Open issues always adopt the current rule's severity/category/routing, so a promoted rule applies to rows created before it. An unreadable current document still counts as a present source: its critical fields exist empty and NEEDS_REVIEW, previous versions' values are cleared (audited `field.cleared`).
